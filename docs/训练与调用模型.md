# 训练与调用：一个模型从哪来、长什么样、怎么用

这份文档回答三个问题：**现在怎么训练模型**、**训练好的模型是什么东西**、**拿到新样品怎么调用它**。

---

## 1. 现在的四个入口

| 入口 | 位置 | 用途 | 会不会留下模型文件 |
|---|---|---|---|
| **Web · 训练并下载模型** | 打开 `/predict`，拉到底部 | 点一下按钮，后台训练完直接给下载链接 | ✅ `.joblib` 或 `.pkl` + 模型卡 |
| **Web · 用模型预测新样品** | 同一张卡片的下半部分 | 选模型 → 拖进新 `.cor` → 出「检出 / 未检出 + 浓度」 | ❌ 结果可下载 CSV |
| `scripts/ml_models.py` | `python scripts/ml_models.py --data data/demo` | 命令行跑同一套评估，打印排行榜 | ❌ 不留 |
| `scripts/train_model.py` | `python scripts/train_model.py --data data/demo` | **选模型 → 验证 → 用全部标准点重新拟合 → 存盘** | ✅ `.joblib` / `.pkl` + `.json` |

Web 上的按钮和 `train_model.py` 调的是**同一个函数**（`scripts/train_model.py` 的 `train()`），
所以界面点出来的模型与命令行跑出来的一模一样，不会出现「界面一套、脚本一套」。

Web 页面每次打开仍在内存里把 9–10 个算法 × 2 种输入各训一遍（demo 约 13–40 秒），
那只是**排行榜**，算完就扔 —— 它能告诉你「哪种算法好」，但不给你明天还能用的东西。

### 为什么「训练」要变成后台任务 + 轮询

Next.js 的 `rewrites` 代理有一条 **30 秒硬上限**：任何单个请求超过 30 秒，
代理就把连接掐掉，浏览器收到一段纯文本 `Internal Server Error`，
而 uvicorn 的 access log 里连这条请求都不会出现（我们就是这么踩进去的，`web.log` 里写着
`Failed to proxy ... [Error: socket hang up] { code: 'ECONNRESET' }`）。

所以训练不能做成「一个 HTTP 请求等到底」：

1. `POST /api/train` 只负责**起一个后台线程**，立刻返回 `{job_id, state: "running"}`（实测 **0.009 秒**）；
2. 浏览器每 2 秒问一次 `GET /api/train/{job_id}`，按钮上显示「正在训练… 47 s」；
3. 训练完成后这个状态接口才把模型信息带回来，同时 `/api/models` 里多一行。

实测：demo 训练 40–172 秒（看机器忙不忙），全程没有任何一个请求超过 1 秒。
同样原因，`/api/regression` 在机器繁忙时也可能超时 —— 前端现在会自动重试 3 次，
因为服务端还在算、缓存填好后重试是毫秒级返回。

## 2. 训练

```bash
# 最省事：自动挑排行榜第一名
python scripts/train_model.py --data data/demo

# 指定算法与输入
python scripts/train_model.py --data data/demo --model SVR-RBF --input features

# 留一批次验证（多个批次时）
python scripts/train_model.py --data data/demo_batches --mode batch

# 看一个已有模型的模型卡
python scripts/train_model.py --describe models/demo_curves_gpr.joblib
```

参数：`--data`（`demo` / `data/demo` / 绝对路径都行）、`--mode electrode|batch`、
`--input auto|curves|features`、`--model auto|<名字>`、`--out models`、`--order 4`、`--ref-frac 0.35`。

实际输出（demo，18 条标准点）：

```
数据文件夹 : /data/workspace/dpv/proj/data/demo
输入       : 整条曲线（18 条标准点 × 80 维）
交叉验证   : 留一电极 18 折 → R²=0.936  RPD=4.07
样本内 R²  : 0.999（只用来确认模型没有退化成常数，不是成绩）

已保存     : models/demo_curves_gpr.joblib (23.0 KB)
模型卡     : models/demo_curves_gpr.json
适用范围   : 1.00e-12 - 1.00e-07 M（6 个浓度、18 条标准点、18 个独立单元）
报告误差   : 约 2.7 倍（报 100 nM 时真值大致在 37 - 270 nM）
检出阈值   : ratio 空白 0.979 ± 0.040（n=3）→ 判「检出」需 ≤ 0.860
```

### 四个数字的含义

- **交叉验证 R² / RPD**：留一电极（或留一批次）的成绩。这是唯一可以引用的成绩。
- **样本内 R²**：模型拟合它自己训练集的能力。只用来确认它没退化成常数，**写论文时不要报这个**。
- **报告误差（倍数）**：`10 ** RMSE(dex)`。R²=0.936 听起来很好，但真话是"报 100 nM，真值可能在 37–270 nM"。
- **检出阈值**：空白的均值 ± 3 SD。回归模型只见过 C>0 的标准点，它不知道"没有分析物"长什么样；这一行才是判"有没有"的依据。

## 3. 生成的模型是什么

两个文件，都在 `models/` 下：

### `<名字>.joblib` —— 真正的模型

一个字典，只有两个键：

```python
{"card": {...}, "model": <sklearn estimator>}
```

`model` 是 sklearn 对象，**不同算法的"长相"差别很大**：

| 算法 | 模型里装的是什么 | 能不能读懂 |
|---|---|---|
| 线性回归 | 81 个系数 + 1 个截距（80 点曲线） | ✅ 完全可读 |
| 岭回归 | 同上，系数被 L2 收缩 | ✅ 可读 |
| PLS | n_components 个载荷向量 + 回归系数 | 🟡 勉强可读 |
| SVR-RBF | 若干个支持向量 + 对偶系数 + gamma/C | ❌ 不可读 |
| 随机森林 | 120 棵树，每棵几十个分裂点 | ❌ 不可读（但能算特征重要性） |
| 梯度提升 | 120 轮残差树 | ❌ 不可读 |
| BP-ANN | 权重矩阵 (80→32→16→1) | ❌ 不可读 |
| 高斯过程 | 核超参 + 全部训练点（本质是查表 + 平滑） | 🟡 核参数可读 |

所以"模型是什么样的"没有统一答案：**它是这个 .joblib 文件本身**，
不是一个公式、不是一个 Excel 表。想讲清楚它学到了什么，靠的是
`predict` 页/CLI 里的**置换重要性**（哪个特征在起作用）和**学习曲线**（数据够不够），
而不是去读权重。

### `<名字>.json` —— 模型卡

人可读的说明书，调用时**必须**用它来复原输入：

```json
{
  "format": "dpv-model/1",
  "model": "高斯过程",
  "input": "curves",
  "grid": [0.8, 0.78, ...],          // 训练时用的电位栅格（80 点）
  "baseline_order": 4,               // 基线多项式阶数
  "ref_frac": 0.35,                  // 内参 QC 门槛
  "metric": "ratio",
  "y_scale": "log10",
  "in_sample_r2": 0.999,
  "cv": {"mode": "electrode", "n_folds": 18, "r2": 0.936, "rpd": 4.07,
         "rmse_dex": 0.432, "factor": 2.70, "rel_err_pct": 170.2},
  "train": {"folder": ".../data/demo", "n_standards": 18, "n_levels": 6,
            "n_units": 18, "unit": "electrode",
            "levels_M": [1e-12, ...], "range_M": [1e-12, 1e-7]},
  "detection": {"metric": "ratio", "n_blanks": 3, "mean": 0.979, "sd": 0.040,
                "sign": -1.0, "cutoff": 0.860},
  "leaderboard": [ ... 前 8 名 ... ]
}
```

**关键点**：曲线怎么预处理（栅格、基线阶数、QC 门槛）全部记在卡里。
调用时按卡复原，新样品才和训练时走同一条流水线 —— 这是"模型能复用"和"模型一换数据就废"的分界线。

## 4. 调用（三种方式，都不用碰命令行也行）

### 方式一：界面

`/predict` 页最下面「用模型预测新样品」→ 选模型 → 选文件（可多选）→ 点「预测」。
结果表直接给「检出 / 未检出 + 预测浓度 + 可能的范围」，可下载 CSV。文件只在内存里过一遍，不落盘。

### 方式二：HTTP

```bash
POST /api/predict
{"model": "demo_curves_gpr", "files": [{"name": "a.cor", "b64": "<base64>"}]}
```

返回 `{ok, model, rows:[{file, detected, pred_M, lo_M, hi_M, I_MB, I_ref, ratio}], bad, log}`。
适合别的系统对接（服务器、批处理脚本、LIMS）。

### 方式三：命令行

```bash
python scripts/predict_with_model.py --model models/demo_curves_gpr.joblib --data data/demo
```

输出（修复 `scale` 判断与空白判定之后重跑，真值 U1 = 5 nM、U2 = 0.5 nM）：

```
模型       : demo_curves_gpr（高斯过程 / curves）
适用范围   : 1 pM - 100 nM
验证成绩   : R²=0.936  RPD=4.07  误差约 2.7 倍

检出阈值   : ratio 空白 0.979 ± 0.040 → 判「检出」需 ≤ 0.860

文件                                       判定           预测浓度                    可能的范围
demo_blank_01.cor                       未检出              —                        —
demo_std_3_02.cor                        检出         100 pM         37.1 pM - 271 pM
demo_std_4_02.cor                        检出           1 nM          370 pM - 2.7 nM
sample_U1.cor                            检出        13.2 nM         4.9 nM - 35.8 nM
sample_U2.cor                            检出         737 pM         273 pM - 1.99 nM
```

同时写出 CSV：`out/predictions_<模型名>_<文件夹>.csv`（`file, detected, pred_M, lo_M, hi_M, group, I_MB, I_ref, ratio`）。

代码里调用：

```python
import joblib
blob = joblib.load("models/demo_curves_gpr.joblib")
model, card = blob["model"], blob["card"]
conc = 10 ** model.predict(X_new)     # X_new 必须按 card["grid"] / card["baseline_order"] 预处理
```

## 5. 怎么读结果（三条硬规矩）

1. **超出适用范围不要用**。`range_M` 之外是外推，模型会给你一个数字，但那个数字没有依据。
2. **"检出"和"浓度"是两件事**。判定来自空白分布（3 SD），浓度来自回归。
   空白被判"未检出"、但回归仍会给一个 4–6 nM 的数字 —— 以判定为准。
3. **区间不是装饰**。`可能的范围` 是 `10 ** ±RMSE(dex)`，即交叉验证时它在新电极上真实表现出的离散度。
   报"100 nM"却不带这个区间，等于把 R²=0.936 当成精确度。

## 6. 两个已经踩过的坑（写在这里，防止再犯）

**坑 1：把 `scale="log10(C)"` 当成 `"log10"` 去比较。**
`evaluate()` 写的字段值是 `"log10(C)"`，如果脚本里写 `== "log10"`，
会静默回落到"直接拟合原始浓度 1e-12~1e-7"。
此时 SVR 的 `epsilon=0.05` 比整个目标范围还大，**所有残差都落在不敏感管里，模型对任何输入都返回同一个常数**。
症状：23 个文件预测出同一个"50 nM"，而交叉验证还报 R²=0.936（因为 CV 里没走这条路径）。
现在 `train_model.py` 加了护栏：拟合后先算样本内预测的标准差，退化成常数就直接拒绝保存。

**坑 2：回归模型不知道"零"是什么。**
训练集只有 C>0（`log10(0) = -inf`），所以空白样品会被报成 4–6 nM。
补法不是把空白硬塞成 `1e-14 M`（那是编数据），而是单独存一份**空白分布**，
判"有没有"用 3 SD 阈值，判"多少"才用回归。模型卡里的 `detection` 块就是干这个的。

## 7. 现在能训什么（实测）

| 数据集 | 标准点 | 浓度个数 | 独立单元 | 最佳模型 | 留一电极 R² / RPD |
|---|---|---|---|---|---|
| `data/demo`（合成） | 18 | 6 | 18 支电极 | 高斯过程 / 整条曲线 | 0.936 / 4.07 |
| `data/demo_batches`（合成，3 批） | 45 | 5 | 66 支电极 | SVR-线性核 / 手工特征 | 0.531 / 1.48 |
| `data/cd36_ngml`（**外部真实数据**，CD36 蛋白） | 55 | 11 | 55 支电极 | 随机森林 / 整条曲线 | 0.992 / 11.55 |
| `data/20261010`（我们的链霉素） | 13 | **1** | 4 支电极 | — | 训不了 |
| 其余 14 个真实文件夹 | 0 | 0 | — | — | 训不了 |

cd36 的 55 条标准点回代误差：中位数 1.0 倍、最大 1.5 倍 —— 但这是**训练集内**，
诚实数字是留一电极的 1.3 倍（RPD 11.55）。

链霉素要训出模型，最小方案是 **9 支电极**：空白 3 + 10 nM 3 + 1 µM 3。
一天的活，就能让上面这条流水线第一次跑在真实数据上。

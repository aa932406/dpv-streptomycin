# 三篇参考文献 → 我们的定量预测模型（逐项对照）

写这份文档的原因：你给的三篇文章（1 篇方法论 + 2 篇 Food Chem 2025）里，
"机器学习"落在电化学传感器上其实只有一件事 —— **用模型把响应曲线映射成浓度**，
并且用 R² / RMSE / RPD 证明它比线性校准更靠得住。下面是逐项对照：他们怎么做的、我们做了什么、差在哪。

## 2. 我们做了什么（`scripts/ml_models.py`）

9 个模型（装了 xgboost 就是 10 个）× 2 套输入 = 18–20 行对比，全部在**同一批标准点、同一套留出规则**下算：

| 模型 | 对应文章里的谁 |
|---|---|
| 线性回归 | 传统校准曲线（I = a + b·logC） |
| 岭回归 | 80 维曲线的正则化线性基线 |
| PLS | 化学计量学标准做法（把曲线压成几个成分） |
| **SVR-RBF** | **文章 B 的主角** |
| **SVR-线性核（LK-SVR）** | **文章 B 的对照组** |
| 随机森林 | 非线性基线 |
| 梯度提升 | 非线性基线（小样本时容易崩） |
| **XGBoost** | **论文里最常见的梯度提升实现**（可选依赖，没装就不显示） |
| **BP-ANN** | **文章 C 的主角** |
| **高斯过程** | 唯一能顺带给出预测不确定度的模型 |

两套输入：**整条基线校正曲线**（80 点，不丢形状信息）与 **12 个手工特征**
（MB 峰电流、内参峰电流、比值、两个峰高/峰位、总电荷、开路电位、起/中/末电流）。

三个指标一个不少（文章 B 报的就是这几个）：

- **R²** —— 但会被浓度范围放大：跨 5 个数量级的 0.94 比跨 1 个数量级的 0.99 更难
- **RMSE（dex）** —— 对数尺度上的平均偏差，0.43 dex ≈ 2.7 倍
- **RPD = 浓度标准差 ÷ 预测误差** —— 论文里最常拿来横向比的数

验证规则（比指标更重要）：

1. **留一电极**，不是留一条扫描 —— 同一支电极连扫 3 次不是 3 个独立样本
2. 超参搜索**只在训练折内**做（嵌套交叉验证），被留出的电极从不参与调参
3. 有多个批次时切到**留一批次**，这是文章 B/C 那种"换个基体还能用"的唯一证明方式

## 4. demo 上的实测数字

演示数据（23 支电极 / 18 条标准点 / 6 个浓度 / 跨 5 个数量级），留一电极：

| 模型 | 输入 | R² | RMSE (dex) | 误差倍数 | RPD |
|---|---|---|---|---|---|
| 高斯过程 | 整条曲线 | 0.936 | 0.43 | 2.70× | 4.07 |
| SVR-RBF | 整条曲线 | 0.936 | 0.43 | 2.71× | 4.06 |
| SVR-RBF | 手工特征 | 0.913 | 0.50 | 3.20× | 3.48 |
| 岭回归 | 整条曲线 | 0.909 | 0.51 | 3.27× | 3.41 |
| 线性回归 | 整条曲线 | 0.890 | 0.57 | 3.68× | 3.10 |
| SVR-线性核 | 整条曲线 | 0.880 | 0.59 | 3.92× | 2.96 |
| PLS | 整条曲线 | 0.819 | 0.73 | 5.32× | 2.42 |
| 随机森林 | 整条曲线 | 0.797 | 0.77 | 5.89× | 2.28 |
| **XGBoost** | 整条曲线 | 0.648 | 1.01 | 10.3× | 1.73 |
| BP-ANN | 整条曲线 | 0.249 | 1.48 | 30.2× | 1.19 |
| 梯度提升 | 整条曲线 | −0.121 | 1.81 | 64.3× | 0.97 |

置换重要性前四：比值 0.78 / MB 峰电流 0.47 / 阴极峰高 0.42 / 阳极峰位 0.076。

**怎么读这张表**

- RBF-SVR 只比线性回归好 0.046 个 R²（0.936 vs 0.890）—— 说明演示数据还在近线性区。
  文章 B 里非线性赢得多，是因为镉在 0.1–200 µM 跨 3 个数量级后校准线明显弯了。
  **你的数据如果也只在一个数量级内，别指望非线性模型能多出什么。**
- 高斯过程与 RBF-SVR 打平（0.9361 vs 0.9357），但它多给一个预测区间 —— 小样本时它的价值在这里。
- BP-ANN 与梯度提升崩掉是**样本量的必然**：18 条标准点、80 维输入，
  神经网络和树的参数量远大于信息量。文章 C 有几百条曲线才撑得起 BP-ANN。
- **XGBoost 在这里只排第 8（R² 0.648）**，但换成 12 个手工特征就跳到 0.882、RPD 3.00，
  和线性回归（0.904）只差一点。这就是「树模型不适合吃 80 维原始曲线、但很能对付少量好特征」的典型表现：
  80 维 + 18 个样本，它在记训练集；12 个有物理含义的特征才让它学到浓度。
  **不是 XGBoost 不好，是这个尺寸的数据喂不动它。** 论文里 XGBoost 出彩的都是几百上千条样本。

## 5. 和论文的差距到底在哪

不是算法，是数据：

| | 文章 B | 我们（demo） | 我们（真实数据） |
|---|---|---|---|
| 标准点 | 几百条 | 18 条 | **0 条**（每个文件夹只有 1 个浓度） |
| 浓度水平 | 0.1–200 µM | 6 个 | 1 个 |
| 独立电极 | 多次重复 | 18 支 | 每条件 1–3 支 |
| 实样 | 11 种饮料 | 无 | 无 |

所以现在的正确说法是：**工具箱齐了，缺的是能被它吃的实验**。
把「校准」页那 9 支电极（空白 3 + 10 nM 3 + 1 µM 3）做出来，这一页就会从"缺什么"变成完整的模型对比表。

再往后：

- **60 支电极 / 3 个批次** → 打开「留一批次」验证，才谈得上文章 B/C 那种"换个基体也能测"
- **加标回收** → 补齐文章 B/C 都有的那一栏（回收率 90–110%、RSD < 5%）

## 6. 复现命令

```bash
# 全部模型 + 两套输入 + 学习曲线 + 重要性（需要 6 条以上标准点、3 个以上浓度）
.venv/bin/python scripts/ml_models.py --data data/demo --mode electrode

# 留一批次（需要 ≥2 个批次）
.venv/bin/python scripts/ml_models.py --data data/demo_batches --mode batch

# 多分析物（Y 是多列，需要多分析物数据）
.venv/bin/python scripts/ml_models.py --data data/demo --multi
```

界面里就是「预测」页，不用命令行。

# 部署说明（Linux 服务器）

一份代码，两种跑法：Windows 本地双击 `run_web.bat`，Linux 服务器跑 `deploy.sh`。
本文只讲服务器。

---

## 1. 架构（先理解这个，再看端口）

```
浏览器 ──HTTP──> Next.js  :3000  (0.0.0.0，对外)
                    │
                    └──反向代理 /api/* ──> FastAPI :8000 (127.0.0.1，只本机)
                                              │
                                              └── scripts/analysis_core.py（全部数学）
```

- **只对外开一个端口**（默认 3000）。API 只听 127.0.0.1，不暴露到公网。
- 浏览器与 API **同源**（都是 3000），所以没有 CORS 问题。
- Next 的 `rewrites` 在 **构建时** 被写进 `routes-manifest.json`，所以 `API_BASE` 必须在 `npm run build` 之前设好。`deploy.sh` 已经这么做了（`API_BASE=http://127.0.0.1:8000`）。**运行时改环境变量不会生效，必须重新构建。**

---

## 2. 三步部署

```bash
# 1) 拉代码（私有仓库，需要 token 或部署密钥）
git clone https://<你的GitHub用户名>:<token>@github.com/aa932406/dpv-streptomycin.git
cd dpv-streptomycin

# 2) 一键部署（自动装依赖、建 venv、构建前端、起 systemd 服务）
sudo bash deploy.sh

# 3) 浏览器打开
#    http://<服务器公网IP>:3000
```

脚本最后会自己 curl 一次 `/api/health` 和 `/verdict` 并打印状态码，然后打印访问地址。

### 参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `--dir` | `/opt/dpv` | 安装目录 |
| `--web-port` | `3000` | 对外端口（监听 0.0.0.0） |
| `--api-port` | `8000` | 内部 API 端口（只听 127.0.0.1） |
| `--user` | 当前 sudo 用户 | 跑服务的系统用户；直接 root 登录时自动建 `dpv` 用户 |
| `--no-systemd` | — | 没有 systemd（容器/老系统）时改用 `start.sh`/`stop.sh` |
| `--no-demo` | — | 不生成合成演示数据（默认会生成 `data/demo`、`data/demo_batches`） |

例：
```bash
sudo bash deploy.sh --dir /srv/dpv --web-port 8080
```

### 脚本做了什么

1. `apt`/`dnf`/`yum` 装 `python3 python3-venv python3-pip curl rsync`；node 缺失或 <18 时用 NodeSource 装 Node 20。
2. `rsync` 把代码同步到安装目录（排除 `.git .venv node_modules .next out`）。
   **`--filter 'P data/*/metadata.csv'` 保护你在界面里保存的元数据，重跑部署不会删掉它。**
3. 建 `.venv`，`pip install -r requirements.txt`。
4. `npm ci`（有 lock 时）+ `npm run build`（构建时注入 `API_BASE`）。
5. 写两个 systemd 单元并 `enable --now`：
   - `dpv-api.service` → `uvicorn server.app:app --host 127.0.0.1 --port 8000`
   - `dpv-web.service` → `next start -p 3000 -H 0.0.0.0`
6. 防火墙（ufw / firewalld 活着时）放行 Web 端口。
7. 自检 + 打印访问地址。

## 3. 打不开怎么办（按顺序查）

1. **云厂商安全组** —— 最常见。阿里云/腾讯云/AWS 要在控制台放行 3000/tcp，服务器本地 ufw 放行了也没用。
2. `systemctl status dpv-web dpv-api` 看两个服务是不是 active。
3. `journalctl -u dpv-web -n 50 --no-pager` 看前端日志；`journalctl -u dpv-api -n 50 --no-pager` 看后端。
4. `curl http://127.0.0.1:8000/api/health` 在本机测 API；`curl http://127.0.0.1:3000/verdict` 测前端。
5. 端口被占：`ss -lntp | grep 3000`，换 `--web-port` 重跑。

### 常见报错

| 现象 | 原因 | 处理 |
|---|---|---|
| 页面 502 / 接口全红 | uvicorn 没起来 | `journalctl -u dpv-api`；多半是 `pip install` 没完成，手动 `.venv/bin/pip install -r requirements.txt` |
| `npm run build` 被杀（OOM） | 小内存机器（1G） | 加 swap 或 `NODE_OPTIONS=--max-old-space-size=2048`；建议 ≥2G 内存 |
| 前端能开但所有数据空 | `API_BASE` 构建时没设 | 重跑 `deploy.sh`（它会重构建），别只重启服务 |
| 图表里中文变方块 | 服务器无中文字体 | 界面文字由浏览器渲染，不受影响；导出 zip 里的 PNG 图内标签本来就是英文 |
| 换端口后页面还是旧的 | 浏览器缓存 / 旧进程 | `systemctl restart dpv-web`，强制刷新（Ctrl+Shift+R） |

## 4. 日常运维

```bash
systemctl status dpv-web dpv-api     # 状态
journalctl -u dpv-web -f             # 前端日志（跟着看）
journalctl -u dpv-api -f             # 后端日志
systemctl restart dpv-web dpv-api    # 重启
systemctl stop dpv-web dpv-api       # 停

# 非 systemd 模式
bash /opt/dpv/start.sh
bash /opt/dpv/stop.sh
```

### 更新代码

```bash
cd /opt/dpv
git pull
sudo bash deploy.sh          # 重新同步 + 重装依赖 + 重新构建 + 重启
```

前端改动**必须重新构建**（`npm run build`），只 `git pull` + `restart` 不会生效。
后端（`server/`、`scripts/`）改完只需 `systemctl restart dpv-api`。

### 数据

- 原始数据放 `data/<日期>/`，例如 `data/20261011/`，界面里下拉框会自动出现。
- 界面「数据」页填的浓度/批次/标签会存成 `data/<日期>/metadata.csv`（`deploy.sh` 重跑时受保护）。
- 生成合成演示数据（没有真实浓度梯度时用来看完整流程）：
  ```bash
  .venv/bin/python scripts/make_demo_data.py --mode single    # data/demo
  .venv/bin/python scripts/make_demo_data.py --mode batches   # data/demo_batches
  .venv/bin/python scripts/make_demo_cv.py                    # data/demo_cv
  ```
- 导入外部数据集（CD36，需要先 clone 那个仓库）：
  ```bash
  .venv/bin/python scripts/import_external.py --src /path/to/biosensors-AI/data/lab_measurements
  ```

## 5. 安全

- 仓库是**私有**的。部署机拉代码用的 token 只放在 shell 历史/部署机本地，**不要提交进仓库**。
- `.gitignore` 已排除 `.instabox_key`、`.env`、`*.pem`、`out/`。
- 如果要给外部访问，建议在前面再放一层 Nginx/Caddy 做 HTTPS 与鉴权；`deploy.sh` 只保证应用能起来，不做 TLS。

## 6. 资源需求

| 项 | 最低 | 建议 |
|---|---|---|
| CPU | 1 核 | 2 核 |
| 内存 | 2 GB（`npm run build` 峰值约 1.2 GB） | 4 GB |
| 磁盘 | 2 GB | 5 GB（数据多时更大） |
| 系统 | Ubuntu 20.04+ / Debian 11+ / Rocky 8+ | Ubuntu 22.04 |

Node 版本：Next 15 需要 **Node ≥ 18.18**，脚本默认装 20。
Python：3.10+（`requirements.txt` 里 numpy/scipy/sklearn 都是常见版本）。
